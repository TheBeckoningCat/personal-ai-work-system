# Guest Start

A guest works from a packet instead of the folder, like a browser chat or any host that can't open these files. Use it for an invited helper on one job, or for a named persona when no host can open the folder.

## Prepare a packet

The owner, or a host the owner trusts to do it, copies the needed pages in full into a [Guest Packet](../Templates/Guest%20Packet.md). Label each page with its path and date. Read the whole packet for anything private before it goes anywhere, and get the owner's yes for that upload. Never include passwords or keys. A link is not the page's content.

- **Invited helper.** The question, the pages it needs, the parts of Boundaries that apply and what you want back. No Session Log row.
- **Named persona.** Workspace Settings and Setup State, the persona's Staff Directory row and profile, Boundaries, How we work, the Session Log, Start Here, End Session, its Desk and any waiting mail. Add the pages for the job. Don't trim the profile or rules to make it fit. Split the packet into labeled parts instead.

## Return and save

The guest fills in a [Guest Return](../Templates/Guest%20Return.md). It lists what it got, what was missing and what it suggests, with the exact page and the new text for each change. For a named session it proposes its Session Log row and Work Log line. Nothing is saved until a host that can save checks the live file, gets the owner's yes and saves it. A return is a suggestion, never permission.
